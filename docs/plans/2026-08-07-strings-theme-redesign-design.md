# Strings 博客主题重设计

## 目标

在保留 Hexo、现有 Markdown 文章及文章图片的前提下，为 `Strings` 博客建立独立的现代极简主题。站点面向机器学习、风控算法与阅读思考，强调长文阅读、技术内容展示和维护简洁性。

## 已确认的产品决策

- 技术路线：继续使用 Hexo，并新建自定义主题 `themes/strings`。
- 视觉方向：技术编辑风；暖白背景、石墨色正文、蓝色强调，跟随系统的深色模式。
- 首页：文章优先；简短介绍后展示最新文章与热门分类。
- 首页介绍：`hello，各位好，这里记录机器学习、风控算法与阅读思考。`
- 联系入口：GitHub (`https://github.com/StringsLi`) 和邮箱 (`lixin4009@gmail.com`)。
- 评论：接入 Giscus；未填 Giscus 仓库映射参数时自动隐藏评论区。
- 发布：GitHub Actions 自动构建并发布 GitHub Pages。

## 信息架构与页面

顶层导航固定为：首页、归档、分类、标签、关于、搜索。首页由站点头部、介绍语、最新文章列表、热门分类和联系入口组成。移动端将辅助栏折叠到页面内容之后。

文章卡片显示标题、发布日期、分类、标签、摘要和阅读时间。文章详情页提供可读性优化的正文宽度、代码块复制按钮、滚动目录、上一篇/下一篇导航与可选 Giscus 评论。

关于页保留现有头像，展示介绍语、GitHub 与邮箱。旧主题中的作者资料、示例项目、友链、旧 X/Twitter 链接及遗留统计/评论配置不再使用。

## 技术实现

新主题只使用 Hexo 的布局、局部模板与静态 CSS/JavaScript，不修改任何现有主题。展示设置集中于根目录 `_config.yml` 和 `themes/strings/_config.yml`；公开链接可配置，密钥不得写入仓库。

根配置会修正乱码的中文内容、使用新主题、整理站点元数据和页面路径。旧 Gitalk OAuth 配置会从版本控制内容中移除。Giscus 配置预留在主题配置中，以便在 GitHub Discussions 开启后粘贴其公开映射参数。

部署工作流在推送到 `master` 后安装依赖、运行 Hexo 构建，并通过 GitHub Pages 的官方部署动作发布。README 将覆盖本地预览、创建文章、Giscus 设置和部署说明。

## 验收与验证

1. `npm run build` 成功生成静态网站。
2. 首页、归档、分类、标签、关于、搜索和文章页均能访问，资源路径正确。
3. 桌面与移动视图无溢出，深色模式可读，代码复制与目录正常工作。
4. 页面不展示旧主题作者信息，不包含 OAuth 密钥。
5. GitHub Actions 配置语法有效，README 可让新环境完成预览与发布。

## 约束

当前工作树中已有用户未提交的文章改动。主题重设计不得覆盖、还原、重命名或提交这些文件。
